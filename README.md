## :dart: O guia para alavancar a sua carreira

> Jenkins é o servidor de automação open source mais usado do mundo para integração e entrega contínua (CI/CD): ele constrói, testa e faz deploy do seu código a cada commit, orquestrando pipelines definidas em código (o `Jenkinsfile`) e conectando praticamente qualquer ferramenta do ecossistema DevOps através de mais de 1.800 plugins. Existe desde 2011 (bifurcado do antigo Hudson), roda em qualquer infraestrutura — de um servidor próprio a um cluster Kubernetes — e continua sendo pré-requisito comum em vagas de DevOps, SRE e engenharia de plataforma no Brasil. Este guia reúne documentação oficial, tutoriais, canais, ferramentas e um capítulo inteiro sobre pipelines e `Jenkinsfile`, além de IA na prática — tudo verificado e organizado para quem está configurando o primeiro job e para quem já mantém pipelines complexas em produção.

## 🔀 Pipelines e Jenkinsfile

> O coração do Jenkins moderno é a Pipeline: um `Jenkinsfile` versionado junto do código descreve estágios, etapas e regras que rodam a cada push. Esta seção reúne a documentação oficial completa sobre o assunto.

- [Using a Jenkinsfile](https://www.jenkins.io/doc/book/pipeline/jenkinsfile/) — Documentação oficial sobre como estruturar, versionar e usar um `Jenkinsfile` no seu repositório.
- [Pipeline best practices](https://www.jenkins.io/doc/book/pipeline/pipeline-best-practices/) — Recomendações oficiais para escrever pipelines mais rápidas, legíveis e fáceis de manter.
- [Pipeline: Multibranch](https://www.jenkins.io/doc/book/pipeline/multibranch/) — Documentação oficial sobre pipelines multibranch, que criam automaticamente um job por branch do repositório.
- [Using Docker with Pipeline](https://www.jenkins.io/doc/book/pipeline/docker/) — Guia oficial para rodar etapas da pipeline dentro de containers Docker.
- [Pipeline Shared Libraries](https://www.jenkins.io/doc/book/pipeline/shared-libraries/) — Documentação oficial sobre como reutilizar código Groovy entre várias pipelines através de bibliotecas compartilhadas.
- [jenkinsci/jenkinsfile-runner](https://github.com/jenkinsci/jenkinsfile-runner) — Ferramenta oficial para executar um `Jenkinsfile` isoladamente, fora de uma instância completa — ótima para testar localmente.

## 🤖 IA na prática

O Jenkins passou a ter uma porta oficial de entrada para agentes de IA: o **MCP Server Plugin**, que implementa o Model Context Protocol e permite que assistentes como GitHub Copilot e Claude conversem diretamente com a sua instância. Veja como aproveitar isso sem virar refém da sugestão errada.

**Para aprender**
- Peça para um assistente de IA (Claude, ChatGPT, Copilot) **explicar** um trecho de `Jenkinsfile` que você não entende, ou traduzir um erro de build em português antes de sair procurando na documentação.
- Use um assistente de IA para gerar um `Jenkinsfile` de partida a partir da descrição do seu projeto e depois valide cada etapa contra a [referência oficial de sintaxe](https://www.jenkins.io/doc/book/pipeline/syntax/) — trate o resultado como rascunho, não como verdade.

**Para trabalhar**
- O [MCP Server Plugin](https://plugins.jenkins.io/mcp-server/) transforma sua instância Jenkins num servidor MCP: expõe jobs, builds, logs e disparo de parâmetros como ferramentas que um assistente de IA pode chamar diretamente do seu editor.
- Veja o [código-fonte e a documentação técnica do plugin](https://github.com/jenkinsci/mcp-server-plugin) para entender exatamente quais operações ficam disponíveis para o agente de IA antes de habilitá-lo num ambiente com dados sensíveis.
- A [CloudBees Unify](https://www.cloudbees.com/unify), plataforma construída por cima do ecossistema Jenkins, anunciou recursos de IA agêntica para pipelines (recomendações, seleção automática de testes e aprovação humana obrigatória antes da execução) — vale acompanhar mesmo que você use o Jenkins "puro".

**Limites e boas práticas**
- Nunca dê a um agente de IA acesso de escrita (disparar builds, alterar credenciais) numa instância de produção sem aprovação humana no meio do caminho — o MCP Server Plugin foi desenhado para ser combinado com controle de permissões, não para substituí-lo.
- Revise **todo** `Jenkinsfile` gerado ou alterado por IA como revisaria o de qualquer colega: rode a pipeline num branch de teste antes de mesclar na `main`.
- Nunca cole credenciais, tokens ou logs de build com dados sensíveis dentro do prompt de uma ferramenta de IA — use variáveis injetadas via [Credentials Binding](https://plugins.jenkins.io/credentials-binding/) e mantenha o segredo fora da conversa.
